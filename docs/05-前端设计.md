## 1. 技术栈与约定

| 项 | 选择 | 强制要求 |
|---|---|---|
| 框架 | Vue 3.5 | 一律用 `<script setup lang="ts">`，不使用 Options API |
| 语言 | TypeScript 5 | `tsconfig.json` 中 `"strict": true`，**不允许 `any`** |
| 构建 | Vite 6 | |
| 状态 | Pinia | 只有跨页面共享的状态才进 store |
| 路由 | Vue Router 4 | |
| UI | Naive UI | 按需引入（已在 Vite 插件中配置） |
| HTTP | Axios | 统一封装，见 §4 |
| 样式 | CSS Modules (`<style scoped>`) + CSS 变量 | 不引入 Tailwind / Sass |
| 包管理 | pnpm | |

### 1.1 为什么不用 TypeScript 的 `any`

这个项目前后端完全分离，接口字段名靠手动同步。**类型是唯一能在编译期发现"后端改了字段名"的手段。**

如果允许 `any`，类型检查形同虚设，接口对不上只会在运行时白屏。

替代方案：
- 拿不准的类型用 `unknown`，然后显式收窄
- 复用生成的后端类型（见 §3）

## 3. 类型定义

### 3.1 来源：从后端 OpenAPI 生成

后端 FastAPI 在开发环境暴露 `/api/openapi.json`。用它自动生成 TS 类型，**避免手写类型和后端脱节**。

```bash
# frontend/package.json
{
  "scripts": {
    "gen:types": "openapi-typescript http://localhost:8000/api/openapi.json -o src/types/generated.ts"
  }
}
```

**工作流**：

1. 后端改接口 → 启动后端
2. `pnpm gen:types`
3. 前端类型报错 → 逼你改代码

**注意**：`generated.ts` 可以提交到 Git（保证 CI 可跑），但**必须在 CI 中校验它与后端一致**，否则会悄悄过期。

### 3.3 状态机（前端侧）

**前端必须知道合法的状态转换顺序**，否则"点圆圈切换"的逻辑会散落在各个组件里。

```ts
// src/utils/status.ts
import type { NodeStatus } from '@/types/api'

/** 点击圆圈时的循环顺序：未开始 → 学习中 → 已掌握 → 未开始 */
export function nextStatus(current: NodeStatus): NodeStatus {
  switch (current) {
    case 'not_started': return 'learning'
    case 'learning':    return 'mastered'
    case 'mastered':    return 'not_started'
    case 'needs_review': return 'mastered'      // 待复习时点击 = 复习通过
  }
}
```

**注意 `needs_review` 的行为**：点击后直接回到 `mastered`（表示"我复习过了"），而不是回到 `not_started`。因为用户点这个圆圈时的意图是"我记得了"。

## 4. API 层

### 4.1 Axios 实例

```ts
// src/api/client.ts
import axios, { AxiosError, type AxiosInstance } from 'axios'
import { useUiStore } from '@/stores/ui'

export interface ApiError {
  code: string
  message: string
  details?: Record<string, unknown>
}

export const client: AxiosInstance = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL ?? '/api/v1',
  timeout: 15_000,
  headers: { 'Content-Type': 'application/json' },
})

// ---- 请求拦截 ----
client.interceptors.request.use((config) => {
  config.headers['X-Request-ID'] = crypto.randomUUID()
  return config
})

// ---- 响应拦截：把错误统一成 ApiError ----
client.interceptors.response.use(
  (response) => response,
  (error: AxiosError<{ error: ApiError }>) => {
    const ui = useUiStore()

    // 网络层错误
    if (!error.response) {
      const msg = error.code === 'ECONNABORTED' ? '请求超时，请重试' : '网络连接失败'
      ui.toast.error(msg)
      return Promise.reject({ code: 'NETWORK_ERROR', message: msg } satisfies ApiError)
    }

    const apiError = error.response.data?.error ?? {
      code: 'UNKNOWN',
      message: `请求失败（${error.response.status}）`,
    }

    // 限流：显示剩余时间
    if (apiError.code === 'RATE_LIMITED') {
      const retryAfter = Number(error.response.headers['retry-after'] ?? 5)
      ui.toast.warning(`${apiError.message}（${retryAfter} 秒后可重试）`)
      return Promise.reject(apiError)
    }

    // AI 不可用：不弹错误，因为调用方会降级
    if (apiError.code === 'AI_UNAVAILABLE') {
      return Promise.reject(apiError)
    }

    // 其余错误统一提示
    ui.toast.error(apiError.message)
    return Promise.reject(apiError)
  },
)
```

**关键设计：`AI_UNAVAILABLE` 不弹全局提示。**

因为调用方（如 `next-step`）会自动降级到规则版，用户看到的是"已切换到基础推荐"，而不是一个报错弹窗。全局弹错误会让用户以为功能坏了。

### 4.2 SSE 封装

`EventSource` 只支持 GET，不支持 POST 和自定义请求体。所以 SSE 用 `fetch` + `ReadableStream` 手工解析。

```ts
// src/api/sse.ts
export interface SseHandlers {
  onStart?: (data: { conversation_id: string; message_id: string }) => void
  onDelta?: (text: string) => void
  onDone?: (data: { message_id: string; usage: Record<string, number> }) => void
  onError?: (err: { code: string; message: string }) => void
}

export async function streamChat(
  body: Record<string, unknown>,
  handlers: SseHandlers,
  signal?: AbortSignal,
): Promise<void> {
  const res = await fetch(`${import.meta.env.VITE_API_BASE_URL ?? '/api/v1'}/assistant/chat`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Accept: 'text/event-stream' },
    body: JSON.stringify(body),
    signal,
  })

  if (!res.ok || !res.body) {
    // 非 SSE 响应（如 503），按普通 JSON 错误处理
    const payload = await res.json().catch(() => null)
    handlers.onError?.(payload?.error ?? { code: 'UNKNOWN', message: '连接失败' })
    return
  }

  const reader = res.body.getReader()
  const decoder = new TextDecoder('utf-8')
  let buffer = ''

  while (true) {
    const { done, value } = await reader.read()
    if (done) break

    buffer += decoder.decode(value, { stream: true })

    // SSE 以空行分隔事件
    const events = buffer.split('\n\n')
    buffer = events.pop() ?? ''            // 最后一段可能不完整，留到下一轮

    for (const raw of events) {
      if (!raw.trim()) continue

      let eventName = 'message'
      let dataStr = ''

      for (const line of raw.split('\n')) {
        if (line.startsWith('event:')) eventName = line.slice(6).trim()
        else if (line.startsWith('data:')) dataStr += line.slice(5).trim()
      }

      let payload: unknown = null
      try {
        payload = dataStr ? JSON.parse(dataStr) : null
      } catch {
        continue                            // 忽略无法解析的块，不要中断整个流
      }

      switch (eventName) {
        case 'start': handlers.onStart?.(payload as never); break
        case 'delta': handlers.onDelta?.((payload as { text: string }).text); break
        case 'done':  handlers.onDone?.(payload as never); break
        case 'error': handlers.onError?.(payload as never); break
      }
    }
  }
}
```

**三个容易踩的坑**

1. **`buffer` 分段问题**：`reader.read()` 返回的 chunk 不保证在事件边界上。必须维护 buffer，按 `\n\n` 切分，留下最后一段。
2. **必须支持 `AbortSignal`**：用户点"停止生成"或离开页面时要能中断。
3. **`onDelta` 的触发频率可能很高**：不要在每次 delta 都触发 Vue 响应式更新。用 `requestAnimationFrame` 或 50ms 节流合并（见 §6.3）。

## 5. 状态管理

### 5.1 Store 划分原则

**只有满足以下条件之一的状态才进 Pinia：**

- 跨多个不相关组件共享
- 需要在路由切换后保持
- 有复杂的异步逻辑

**以下情况不进 store**：

- 单个组件内的表单状态 → `ref` 就够了
- 从 props 能推导出的值 → `computed`
- 服务端数据的简单展示 → 可以在组件内 `ref` + `onMounted`

> **反模式警告**：把所有接口数据都塞进 store 是常见的过度设计。它会让数据流变得难以追踪，且引入大量无意义的同步代码。

### 5.2 route store（核心）

```ts
// src/stores/route.ts
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import type { RoadmapDetail, RoadmapNode } from '@/types/api'
import * as routeApi from '@/api/routes'

export const useRouteStore = defineStore('route', () => {
  const detail = ref<RoadmapDetail | null>(null)
  const loading = ref(false)

  const allNodes = computed<RoadmapNode[]>(() =>
    detail.value?.modules.flatMap(m => m.nodes) ?? []
  )

  const nodeMap = computed<Map<string, RoadmapNode>>(() =>
    new Map(allNodes.value.map(n => [n.id, n]))
  )

  async function load(routeId: string) {
    loading.value = true
    try {
      detail.value = await routeApi.getDetail(routeId)
    } finally {
      loading.value = false
    }
  }

  /** 局部更新单个节点的进度，避免整棵树重载 */
  function patchNodeProgress(nodeId: string, progress: Partial<RoadmapNode['progress']>) {
    const node = nodeMap.value.get(nodeId)
    if (!node) return
    Object.assign(node.progress, progress)
  }

  /** 重新计算受影响节点的 is_startable（本地乐观更新用） */
  function recomputeStartable() {
    if (!detail.value) return
    const p = (id: string) => nodeMap.value.get(id)?.progress.status ?? 'not_started'
    for (const node of allNodes.value) {
      node.is_startable = node.depends_on.every(dep => p(dep) === 'mastered')
    }
  }

  return { detail, loading, allNodes, nodeMap, load, patchNodeProgress, recomputeStartable }
})
```

### 5.3 乐观更新

**核心交互的响应必须立即反馈，不能等接口返回。**

```ts
// src/composables/useOptimisticStatus.ts
import { useRouteStore } from '@/stores/route'
import { updateProgress } from '@/api/progress'
import { nextStatus } from '@/utils/status'
import type { NodeStatus } from '@/types/api'

export function useOptimisticStatus() {
  const routeStore = useRouteStore()
  const pending = new Map<string, NodeStatus>()

  async function cycleStatus(nodeId: string) {
    const node = routeStore.nodeMap.get(nodeId)
    if (!node) return

    const previous = node.progress.status
    const next = nextStatus(previous)

    // 1. 立即更新本地（乐观）
    routeStore.patchNodeProgress(nodeId, {
      status: next,
      ...(next === 'mastered' ? { mastered_at: new Date().toISOString() } : {}),
    })
    routeStore.recomputeStartable()

    // 2. 防止同一节点并发请求
    if (pending.has(nodeId)) return
    pending.set(nodeId, next)

    try {
      // 3. 发请求
      const result = await updateProgress(nodeId, { status: next })

      // 4. 用服务端返回的真实数据校正（mastered_at、review_due_at 等只有服务端知道）
      routeStore.patchNodeProgress(nodeId, {
        status: result.status,
        mastery: result.mastery,
        review_stage: result.review_stage,
        mastered_at: result.mastered_at,
        review_due_at: result.review_due_at,
      })

      // 5. 提示解锁
      if (result.unlocked_nodes.length > 0) {
        showUnlockToast(result.unlocked_nodes)
      }
    } catch {
      // 6. 失败回滚
      routeStore.patchNodeProgress(nodeId, { status: previous })
      routeStore.recomputeStartable()
    } finally {
      pending.delete(nodeId)
    }
  }

  return { cycleStatus }
}
```

**为什么需要 `pending` 去重**：乐观更新后本地状态已经变了，但如果用户连点三次，会产生三个请求。用 Map 记录进行中的请求，避免竞态。

### 6.3 NoteEditor（自动保存）

笔记是本产品使用频率最高的输入，**自动保存必须可靠**。

```vue
<!-- src/components/note/NoteEditor.vue -->
<script setup lang="ts">
import { ref, watch, onBeforeUnmount } from 'vue'
import { updateNote } from '@/api/notes'

const props = defineProps<{ nodeId: string; modelValue: string }>()
const content = ref(props.modelValue)
const state = ref<'idle' | 'dirty' | 'saving' | 'saved' | 'error'>('idle')

let timer: ReturnType<typeof setTimeout> | null = null
let inflight: AbortController | null = null

watch(content, () => {
  state.value = 'dirty'
  if (timer) clearTimeout(timer)
  timer = setTimeout(save, 800)          // 800ms 防抖
})

async function save() {
  if (state.value === 'saving' || state.value === 'saved') return

  // 取消上一次未完成的请求，避免乱序覆盖
  inflight?.abort()
  inflight = new AbortController()

  state.value = 'saving'
  try {
    await updateNote(props.nodeId, content.value, inflight.signal)
    state.value = 'saved'
    setTimeout(() => { if (state.value === 'saved') state.value = 'idle' }, 2000)
  } catch (e) {
    if ((e as Error).name === 'AbortError') return
    state.value = 'error'
  }
}

// 离开页面前强制保存
function flush() {
  if (timer) clearTimeout(timer)
  if (state.value === 'dirty') save()
}

onBeforeUnmount(flush)
window.addEventListener('beforeunload', flush)

const STATE_TEXT = {
  idle: '', dirty: '未保存', saving: '保存中…', saved: '已保存', error: '保存失败，正在重试',
} as const
</script>

<template>
  <div class="note-editor">
    <label class="note-label">
      我的笔记
      <span class="note-state" :data-state="state">{{ STATE_TEXT[state] }}</span>
    </label>
    <textarea
      v-model="content"
      class="note-textarea"
      placeholder="用自己的话写：这个知识点在讲什么、我卡在哪、哪一刻想通了……"
    />
  </div>
</template>
```

**三个关键点**

1. **防抖 800ms**：太短会频繁请求，太长会在切页面时丢内容
2. **AbortController 取消旧请求**：防止先发的慢请求后到，覆盖新内容（经典竞态）
3. **`beforeunload` 强制保存**：用户直接关标签页时保住内容

#### StreamingText 的渲染性能

**流式输出每秒可能产生几十次 delta。直接绑定到响应式状态会导致每个字都触发一次组件更新。**

```vue
<!-- src/components/assistant/StreamingText.vue -->
<script setup lang="ts">
import { ref, onBeforeUnmount } from 'vue'

const props = defineProps<{ stream: AsyncIterable<string> }>()

const displayed = ref('')
let buffer = ''
let rafId: number | null = null

function flush() {
  if (buffer) {
    displayed.value += buffer
    buffer = ''
  }
  rafId = null
}

async function run() {
  for await (const chunk of props.stream) {
    buffer += chunk
    // 每帧最多更新一次 DOM
    if (rafId === null) rafId = requestAnimationFrame(flush)
  }
  flush()                                   // 收尾
}

onBeforeUnmount(() => { if (rafId) cancelAnimationFrame(rafId) })

run()
</script>

<template>
  <div class="streaming-text">{{ displayed }}<span class="caret" /></div>
</template>
```

**为什么用 `requestAnimationFrame`**：人眼分辨不出每帧内的多次更新。把 N 次状态更新合并到每帧一次，可以显著降低渲染压力。这在长回答时差异明显。

- 不做自定义主题系统
- 不做复杂的过渡动画（只保留必要的 `transition: 0.15s`）
- 不做暗色模式（V2 再说）
- 移动端只保证"能用"，不做精细适配

## 9. 开发顺序建议

前端不要一次性写完。**按里程碑的验收标准，每个里程碑只做必要的页面。**

| 里程碑 | 前端要做的 |
|---|---|
| M1 | 空壳：路由 + 布局 + 健康检查连通 |
| M2 | `RoadmapView` 静态渲染（读数据、展示模块和节点，不能操作） |
| M3 | 节点状态切换 + 乐观更新 + 笔记编辑与保存 |
| M4 | 概览统计 + 下一步推荐（规则版）+ 模板导入 + 导出 |
| M5 | `AssistantView`（SSE 流式）+ 下一步的 AI 解释 |
| M6 | `ReviewView` + `TasksView` + 作业轮询 |
| M7 | 打磨：空状态、错误处理、加载骨架、快捷键 |

**每个里程碑结束时，前端必须能跑通该里程碑的完整用户操作路径**，不是"页面画好了"。
