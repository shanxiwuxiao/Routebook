## 1. 通用约定

### 1.1 URL 规范

| 规则 | 示例 |
|---|---|
| 统一前缀 `/api/v1` | `/api/v1/routes` |
| 资源用复数名词 | `/routes` `/nodes` `/tasks` |
| 层级关系写在路径里 | `/routes/{route_id}/nodes` |
| 动作型接口用子路径 + 动词 | `/nodes/{node_id}/progress`（其实这也是资源） |
| 不允许动词出现在路径中（除少数例外） | ❌ `/getRoutes` ✅ `/routes` |

**例外**：`/assistant/next-step`、`/assistant/chat`、`/assistant/plan` 这类"计算型"接口，因为它们不产生可直接寻址的资源，用动词是合理的。

### 1.2 统一响应格式

**成功响应**：直接返回资源本身，不包裹 `{data: ...}`。

```jsonc
// GET /api/v1/routes
[
  { "id": "...", "title": "..." }
]

// GET /api/v1/routes/{id}
{ "id": "...", "title": "...", "nodes": [...] }
```

> **为什么不做 `{code, data, message}` 包装**：HTTP 状态码已经表达了成功与否，再包一层是冗余的。而且这会破坏 OpenAPI schema 的直出能力，前端类型生成会多一层嵌套。

**列表响应**：需要分页的接口返回分页信封。

```jsonc
{
  "items": [ /* ... */ ],
  "total": 128,
  "page": 1,
  "page_size": 20,
  "has_next": true
}
```

### 1.3 错误响应格式

**所有错误响应格式统一**：

```jsonc
{
  "error": {
    "code": "DEPENDENCY_CYCLE",           // 机器可读的稳定错误码
    "message": "添加该依赖会形成循环引用",   // 人类可读，可直接展示给用户
    "details": {                           // 可选，附加上下文
      "cycle_path": ["向量数据库", "搭建完整 RAG 流程", "文本切分策略"]
    }
  }
}
```

**实现方式**：自定义异常 + 全局异常处理器。

```python
# core/exceptions.py
class AppError(Exception):
    """所有业务异常的基类"""
    code: str = "INTERNAL_ERROR"
    http_status: int = 500
    message: str = "服务器内部错误"

    def __init__(self, message: str | None = None, details: dict | None = None):
        self.message = message or self.__class__.message
        self.details = details or {}
        super().__init__(self.message)


class NotFoundError(AppError):
    code = "NOT_FOUND"
    http_status = 404
    message = "资源不存在"


class DependencyCycleError(AppError):
    code = "DEPENDENCY_CYCLE"
    http_status = 409
    message = "添加该依赖会形成循环引用"


class ResourceLimitError(AppError):
    code = "RESOURCE_LIMIT"
    http_status = 409
    message = "每个节点最多 2 条资源"


class RateLimitedError(AppError):
    code = "RATE_LIMITED"
    http_status = 429
    message = "操作过于频繁，请稍后再试"


class AIUnavailableError(AppError):
    code = "AI_UNAVAILABLE"
    http_status = 503
    message = "AI 服务暂时不可用"
```

```python
# main.py 中注册
@app.exception_handler(AppError)
async def app_error_handler(request: Request, exc: AppError):
    return JSONResponse(
        status_code=exc.http_status,
        content={"error": {"code": exc.code, "message": exc.message, "details": exc.details}},
    )

@app.exception_handler(RequestValidationError)
async def validation_handler(request: Request, exc: RequestValidationError):
    return JSONResponse(
        status_code=422,
        content={"error": {
            "code": "VALIDATION_ERROR",
            "message": "请求参数校验失败",
            "details": {"errors": exc.errors()},
        }},
    )
```

### 1.4 错误码总表

| code | HTTP | 含义 | 前端处理建议 |
|---|---|---|---|
| `VALIDATION_ERROR` | 422 | 参数校验失败 | 高亮字段 |
| `NOT_FOUND` | 404 | 资源不存在 | 提示并返回列表页 |
| `DEPENDENCY_CYCLE` | 409 | 依赖成环 | 展示环路径 |
| `RESOURCE_LIMIT` | 409 | 超出数量限制 | 提示先删一条 |
| `DUPLICATE` | 409 | 唯一约束冲突 | 提示已存在 |
| `RATE_LIMITED` | 429 | 触发限流 | 显示倒计时 |
| `AI_UNAVAILABLE` | 503 | LLM 不可用 | **自动降级到规则版** |
| `AI_INVALID_OUTPUT` | 502 | LLM 输出不合契约 | 提示重试 |
| `EXPORT_TOO_LARGE` | 413 | 导出数据过大 | 提示分批导出 |
| `INTERNAL_ERROR` | 500 | 未捕获异常 | 通用错误提示 |

### 1.5 认证

**MVP 阶段：无认证。** 单用户模式。

```python
# core/security.py
async def get_current_user_id(session: AsyncSession = Depends(get_session)) -> UUID:
    """
    MVP：返回默认用户 ID。
    V1 加认证后，此处改为解析 JWT / Session，其余代码零改动。
    """
    user_id = await session.scalar(
        select(User.id).where(User.settings["owner_key"].astext == "default").limit(1)
    )
    if user_id is None:
        raise RuntimeError("默认用户不存在，请先执行 seed 脚本")
    return user_id
```

**为什么这样设计**：所有 service 方法签名都是 `(user_id, ...)`，将来加认证只需替换这一个函数。见 `03` ADR-005。

### 1.6 幂等性

| 接口类型 | 幂等性要求 |
|---|---|
| `GET` / `HEAD` | 天然幂等 |
| `PUT`（全量替换） | 必须幂等。同一请求执行 N 次结果相同 |
| `PATCH`（部分更新） | 不保证幂等（如果涉及计数器） |
| `POST`（创建） | 不幂等，但**相同内容不应产生重复数据**（业务层查重） |
| `DELETE` | 必须幂等。删除不存在的资源返回 204，不返回 404 |

**进度更新用 `PUT` 而不是 `PATCH`**：因为状态是覆盖写，传什么就是什么，不涉及增量。这样天然幂等，前端可以放心重试。

```python
# services/route_service.py
async def get_detail(self, route_id: UUID, user_id: UUID) -> RouteDetail:
```

### 3.2 节点

#### POST `/api/v1/routes/{route_id}/nodes`

```jsonc
// 请求
{
  "title": "向量与相似度",              // 必填
  "summary": "",                       // 可选
  "exit_criteria": "能解释余弦相似度在干什么",  // 可选
  "level": 2,                          // 可选，默认 1
  "module_name": "RAG 检索增强",         // 可选，默认 ""
  "depends_on": ["a1b2c3d4-..."],      // 可选，前置节点 ID 数组
  "insert_after_position": 3           // 可选，插入位置。不传则追加到模块末尾
}
```

**实现要点**

- 创建节点时必须校验 `depends_on` 的节点都属于同一条路线，否则 400
- 必须做环检测（新节点没有反向边，理论上不会成环，但 `depends_on` 可能存在互相引用）
- `position` 计算：如果传了 `insert_after_position`，则该位置后的节点 `position + 1`

**响应 201**：返回完整节点对象。

#### PATCH `/api/v1/nodes/{node_id}`

同 POST 的字段，全部可选。

#### PUT `/api/v1/nodes/{node_id}/dependencies`

**全量替换**语义：传什么就是什么。

```jsonc
// 请求
{ "depends_on": ["a1b2c3d4-...", "e5f6a7b8-..."] }
```

**必须校验**（按顺序）：

1. 所有 ID 都属于同一路线 → 否则 400 `VALIDATION_ERROR`
2. 不能依赖自己 → 否则 400 `VALIDATION_ERROR`
3. **不能成环** → 否则 409 `DEPENDENCY_CYCLE`，`details.cycle_path` 返回环路径

**环检测实现**（见 `02` §3.4 的递归 CTE）：

```python
# repositories/node_repo.py
async def would_create_cycle(
    self, node_id: UUID, new_dep_id: UUID, session: AsyncSession
) -> list[UUID] | None:
    """
    判断添加 new_dep_id → node_id 是否成环。
    等价于：从 new_dep_id 出发沿 depends_on 能否到达 node_id。
    返回环路径（用于错误提示），无环返回 None。
    """
    sql = text("""
        WITH RECURSIVE reach AS (
            SELECT depends_on_id AS id, ARRAY[depends_on_id] AS path
            FROM node_dependencies WHERE node_id = :dep
            UNION ALL
            SELECT nd.depends_on_id, r.path || nd.depends_on_id
            FROM node_dependencies nd
            JOIN reach r ON nd.node_id = r.id
            WHERE NOT nd.depends_on_id = ANY(r.path)     -- 防死循环
              AND array_length(r.path, 1) < 20            -- 深度上限
        )
        SELECT path FROM reach WHERE id = :target LIMIT 1
    """)
    row = await session.execute(sql, {"dep": new_dep_id, "target": node_id})
    result = row.scalar_one_or_none()
    return list(result) if result else None
```

> **注意 `NOT ... = ANY(r.path)` 这一句。** 它防止递归 CTE 在已存在的环里无限循环。即使前面有 CHECK 约束和业务校验，数据库里也可能因为手工操作出现环，查询层必须自我保护。

**响应 200**：返回更新后的依赖列表。

#### DELETE `/api/v1/nodes/{node_id}`

**响应 204**。级联删除该节点的依赖边、进度、笔记、资源、chunks。

**注意**：删除节点后，依赖它的其他节点会失去一个前置。这不影响正确性（推荐算法会重新计算），但前端应该提示"有 3 个节点依赖它，删除后它们的前置会减少"。

### 3.3 进度

#### PUT `/api/v1/nodes/{node_id}/progress`

**请求**

```jsonc
{
  "status": "mastered",     // not_started | learning | mastered | needs_review
  "mastery": 4              // 可选，0–5
}
```

**服务端行为**（这是本产品最核心的一段业务逻辑）：

```python
async def update_progress(self, node_id: UUID, user_id: UUID, body: ProgressUpdate) -> ProgressOut:
    node = await self.node_repo.get_or_404(node_id)

    # 1. 取或创建进度记录（懒创建）
    prog = await self.progress_repo.get_or_create(user_id, node_id)
    old_status = prog.status

    # 2. 状态流转校验（见下方状态机）
    validate_transition(old_status, body.status)

    # 3. 应用变更
    prog.status = body.status
    if body.mastery is not None:
        prog.mastery = body.mastery

    if body.status == "mastered":
        # 3a. 首次标记掌握，或从 needs_review 回到 mastered
        if old_status != "mastered":
            prog.mastered_at = utcnow()
            prog.review_stage = 0
            intervals = await self.get_review_intervals(user_id)
            prog.review_due_at = utcnow() + timedelta(days=intervals[0])

    elif body.status == "not_started":
        # 3b. 撤销：清空复习状态
        prog.mastered_at = None
        prog.review_stage = 0
        prog.review_due_at = None

    elif body.status == "learning":
        prog.last_studied_at = utcnow()

    if body.status != "mastered":
        prog.last_studied_at = utcnow()

    await self.progress_repo.save(prog)

    # 4. 异步触发：笔记重新向量化（不阻塞响应）
    if body.status == "mastered":
        enqueue_embed_note.delay(str(node_id), str(user_id))   # 只对掌握的节点做，省成本

    return ProgressOut.model_validate(prog)
```

**状态机**

```
          ┌──────────────────────────────────────┐
          ▼                                      │
    not_started ──(开始学)──► learning ──(达成出口条件)──► mastered
          ▲                      │                        │
          │                      │                        │（到复习时间）
          └──(撤销/清空)─────────┴────(撤销)─────── nees_review
                                                          │
                                              （复习通过）──┘ → mastered
```

**合法转换表**

| from \ to | not_started | learning | mastered | needs_review |
|---|---|---|---|---|
| `not_started` | ✅ | ✅ | ✅（用户可能直接会） | ❌ |
| `learning` | ✅ | ✅ | ✅ | ❌ |
| `mastered` | ✅ | ✅ | ✅ | ✅ |
| `needs_review` | ✅ | ✅ | ✅ | ✅ |

**关键设计决策：允许任意状态直接跳到 `mastered`。**

理由：用户可能已经会了某个知识点（比如本来就会 Python），强制他先点"学习中"再点"已掌握"是无意义的仪式感。见 `01` 交互原则 3（不禁止操作）。

**响应 200**

```jsonc
{
  "node_id": "a1b2c3d4-...",
  "status": "mastered",
  "mastery": 4,
  "review_stage": 0,
  "mastered_at": "2026-10-12T14:00:00Z",
  "review_due_at": "2026-10-13T14:00:00Z",
  "unlocked_nodes": [                     // 因为这次操作而变得可开始的节点
    { "id": "e5f6a7b8-...", "title": "调用大模型 API" }
  ]
}
```

```python
async def next_step(self, user_id: UUID, route_id: UUID, with_explanation: bool) -> NextStepOut:
    # 1. 规则先行：算出候选（纯 SQL，见 02 §4.2）
    candidates = await self.node_repo.list_startable(route_id, user_id)
    if not candidates:
        return NextStepOut(source="rule", recommendations=[], ...)

    # 2. 规则排序（AI 不可用时的兜底顺序）
    ranked = sorted(candidates, key=lambda n: (n.level, n.position))[:5]

    if not with_explanation:
        return NextStepOut(source="rule", recommendations=[to_rec(n) for n in ranked[:3]], ...)

    # 3. 让 AI 排序 + 生成解释，但严格约束在候选集内
    try:
        snapshot = await self.context_builder.build_progress_snapshot(user_id, route_id)
        llm_out = await asyncio.wait_for(
            self.llm.complete_json(
                prompt=NEXT_STEP_PROMPT.render(
                    snapshot=snapshot,
                    candidates=[{"id": str(n.id), "title": n.title, "level": n.level,
                                 "exit_criteria": n.exit_criteria} for n in candidates],
                ),
                schema=NextStepLLMOutput,          # 强约束
            ),
            timeout=settings.AI_NEXT_STEP_TIMEOUT_SECONDS,   # 默认 5 秒
        )

        # 4. 输出合法性校验 —— 关键防线，见 06 §5.3
        valid_ids = {str(n.id) for n in candidates}
        filtered = [r for r in llm_out.recommendations if r.node_id in valid_ids]

        if not filtered:
            # AI 返回的 ID 全是幻觉 → 整体降级
            logger.warning("next_step.ai_hallucinated", returned=[r.node_id for r in llm_out.recommendations])
            return NextStepOut(source="rule", recommendations=[to_rec(n) for n in ranked[:3]], ...)

        return NextStepOut(source="ai", recommendations=filtered, ...)

    except (asyncio.TimeoutError, AIUnavailableError, ValidationError) as exc:
        logger.warning("next_step.degraded", error=str(exc))
        return NextStepOut(source="rule", recommendations=[to_rec(n) for n in ranked[:3]], ...)
```

**注意 `source` 字段。** 前端要明确告诉用户"这是 AI 的建议"还是"这是按规则算的"。**不要让用户误以为 AI 说的话都是 AI 生成的**——这是产品诚实性的问题。

### 4.2 事务边界

**原则：一个 service 方法 = 一个事务。**

```python
# db/session.py
async def get_session() -> AsyncIterator[AsyncSession]:
    async with async_session_maker() as session:
        try:
            yield session
            await session.commit()
        except Exception:
            await session.rollback()
            raise
```

**跨 service 调用时不要开新事务。** 复用同一个 session（通过依赖注入传递）。

**例外：AI 调用绝不在事务内。**

```python
# ❌ 错误：事务持有期间等 LLM 30 秒
async def bad(self, ...):
    async with session.begin():
        job = await self.job_repo.create(...)
        result = await self.llm.complete(...)      # 数据库连接被占住 30 秒！
        await self.job_repo.update(job.id, result)

# ✅ 正确
async def good(self, ...):
    job = await self.job_repo.create(...)           # 事务 1：独立提交
    await session.commit()

    result = await self.llm.complete(...)           # 无事务持有

    await self.job_repo.update(job.id, result)      # 事务 2：独立提交
    await session.commit()
```

**这是最常见的数据库事故：事务中做外部 IO，导致连接池耗尽。**

```python
# api/deps.py
```

### 5.2 任务实现模板

**所有 AI 任务必须遵循这个模板**：幂等 + 状态更新 + 异常处理。

```python
# tasks/ai_tasks.py
@celery_app.task(
    bind=True,
    name="routebook.tasks.ai_tasks.generate_plan",
    queue="ai_heavy",
    max_retries=2,
    retry_backoff=True,
    retry_backoff_max=120,
    acks_late=True,
)
def generate_plan(self, job_id: str) -> dict:
    """生成学习计划。幂等：以 job_id 为键，已成功则直接返回。"""
    job_uuid = UUID(job_id)

    # 1. 幂等检查（在同步上下文里，用同步 session）
    with SyncSessionLocal() as session:
        job = session.get(AIJob, job_uuid)
        if job is None:
            logger.error("job.not_found", job_id=job_id)
            return {"ok": False, "error": "job not found"}
        if job.status == "succeeded":
            logger.info("job.already_done", job_id=job_id)
            return {"ok": True, "skipped": True}

        job.status = "running"
        job.started_at = utcnow()
        job.celery_id = self.request.id
        session.commit()

        payload = job.payload
        user_id = job.user_id

    # 2. 执行（无数据库事务持有）
    try:
        result = asyncio.run(_generate_plan_async(user_id, payload))

        # 3. 落库
        with SyncSessionLocal() as session:
            job = session.get(AIJob, job_uuid)
            job.status = "succeeded"
            job.result = result
            job.finished_at = utcnow()

            for t in result["tasks"]:
                session.add(StudyTask(
                    user_id=user_id,
                    node_id=t.get("node_id"),
                    title=t["title"],
                    description=t.get("description", ""),
                    due_date=parse_date(t.get("due_date")),
                    source="ai_plan",
                    priority=t.get("priority", 1),
                ))
            session.commit()

        return {"ok": True}

    except SoftTimeLimitExceeded:
        _mark_failed(job_uuid, "AI 调用超时")
        raise
    except Exception as exc:
        logger.exception("plan.failed", job_id=job_id)
        if self.request.retries >= self.max_retries:
            _mark_failed(job_uuid, str(exc))
        raise
```

**关键点说明**

1. **`asyncio.run()` 桥接**：Celery 是同步的，而我们的 service 是 async。用 `asyncio.run()` 启动一个独立事件循环。
   ⚠️ **不能在任务里复用 FastAPI 的 event loop**，那会导致死锁。

2. **同步 session**：Celery task 里用 `SyncSessionLocal`（psycopg 驱动），不要用 `AsyncSession`。这是为什么 `pyproject.toml` 同时需要 `asyncpg` 和 `psycopg`。

3. **幂等键是 `job_id`**：因为 `acks_late=True`，任务可能重复投递，必须先查状态。

4. **`SoftTimeLimitExceeded` 必须单独捕获**：超时是最常见的失败模式，要写入明确的原因，而不是一句 "Task timed out"。

### 5.3 僵尸作业清理

worker 崩溃时，`ai_jobs.status` 会永远停在 `running`。

```python
@celery_app.task(name="routebook.tasks.maintenance.cleanup_stale_jobs", queue="maintenance")
def cleanup_stale_jobs() -> dict:
    """把超过 15 分钟仍在 running 的作业标记为失败。"""
    cutoff = utcnow() - timedelta(minutes=15)
    with SyncSessionLocal() as session:
        result = session.execute(
            update(AIJob)
            .where(AIJob.status == "running", AIJob.started_at < cutoff)
            .values(status="failed", error="作业超时未完成（worker 可能已崩溃）", finished_at=utcnow())
        )
        session.commit()
        return {"cleaned": result.rowcount}
```

**没有这个任务，前端会永远轮询下去。**

### 9.1 健康检查

```python
@app.get("/health", tags=["system"])
async def health(redis: Redis = Depends(get_redis)) -> dict:
    checks = {"api": "ok"}

    try:
        async with engine.connect() as conn:
            await conn.execute(text("SELECT 1"))
        checks["database"] = "ok"
    except Exception as exc:
        checks["database"] = f"error: {exc.__class__.__name__}"

    try:
        await redis.ping()
        checks["redis"] = "ok"
    except Exception as exc:
        checks["redis"] = f"error: {exc.__class__.__name__}"

    overall = "ok" if all(v == "ok" for v in checks.values()) else "degraded"
    return {"status": overall, "checks": checks, "version": "1.0.0"}
```

**注意**：健康检查**不检查 RabbitMQ**。因为队列挂了不影响核心功能（ADR-001 的降级原则），健康检查不应因此报告不健康。Celery 的状态通过 Flower 单独监控。
