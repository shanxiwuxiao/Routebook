# 07 · 部署与运维

> 配置项定义见 `04-后端设计.md` §8。架构见 `03-技术架构.md`。

## 1. 部署形态

本项目有两种运行形态，**用同一套 Docker 镜像，只是 compose 文件不同**。

| 形态 | 文件 | 用途 | 数据库数据 |
|---|---|---|---|
| 开发 | `deploy/docker-compose.dev.yml` | 只跑基础设施，前后端本地跑 | Docker volume |
| 生产 | `deploy/docker-compose.yml` | 全部容器化 | Docker volume + 每日备份 |

## 2. 环境要求

### 2.1 服务器

| 项 | 最低 | 推荐 | 说明 |
|---|---|---|---|
| CPU | 2 核 | 4 核 | |
| 内存 | 4 GB | 8 GB | PostgreSQL 1G + RabbitMQ 512M + 其余 ~1.5G |
| 磁盘 | 20 GB | 40 GB SSD | SSD 对数据库性能影响很大 |
| 系统 | Ubuntu 22.04 LTS | Ubuntu 24.04 LTS | |
| 网络 | 公网 IP | 域名已解析 | 用于 HTTPS |

**关于内存**：`uvicorn` 单 worker 约 150MB，`celery worker` 约 200MB（AI 任务会临时升高），PostgreSQL 约 300MB–1GB（取决于 shared_buffers 配置），RabbitMQ 约 250MB，Redis 约 50MB。加上系统开销，4GB 是舒适起点。

**如果内存紧张**（2GB 机器）：

- PostgreSQL `shared_buffers` 降到 128MB
- 只跑 1 个 Celery worker（不要按队列拆多个 worker）
- 考虑用 SQLite 替代 PostgreSQL —— **但 pgvector 不可用，RAG 功能需要放弃**

### 2.2 本地开发

| 工具 | 版本 | 安装 |
|---|---|---|
| Docker Desktop | 最新 | 官网 |
| uv | 最新 | `winget install astral-sh.uv` |
| Node.js | 22 LTS | 官网 |
| pnpm | 9+ | `corepack enable && corepack prepare pnpm@latest --activate` |

## 3. Docker Compose

### 3.1 生产配置

**`deploy/docker-compose.yml`**

```yaml
name: routebook

services:
  db:
    image: pgvector/pgvector:pg16
    container_name: routebook-db
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
      POSTGRES_INITDB_ARGS: "--encoding=UTF8 --locale=C"
    volumes:
      - db_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s
    # 不暴露端口到宿主机 —— 只有容器网络内可访问
    expose:
      - "5432"
    deploy:
      resources:
        limits:
          memory: 1g

  redis:
    image: redis:7-alpine
    container_name: routebook-redis
    restart: unless-stopped
    command: >
      redis-server
      --appendonly yes
      --maxmemory 256mb
      --maxmemory-policy allkeys-lru
      --save 900 1
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 3s
      retries: 5
    expose:
      - "6379"
    deploy:
      resources:
        limits:
          memory: 320m

  rabbitmq:
    image: rabbitmq:3.13-management-alpine
    container_name: routebook-rabbitmq
    restart: unless-stopped
    environment:
      RABBITMQ_DEFAULT_USER: ${RABBITMQ_USER}
      RABBITMQ_DEFAULT_PASS: ${RABBITMQ_PASSWORD}
      RABBITMQ_DEFAULT_VHOST: /
    volumes:
      - rabbitmq_data:/var/lib/rabbitmq
    healthcheck:
      test: ["CMD", "rabbitmq-diagnostics", "-q", "ping"]
      interval: 15s
      timeout: 10s
      retries: 5
      start_period: 60s
    expose:
      - "5672"
    # 管理界面不对外暴露。需要时用 SSH 隧道：
    # ssh -L 15672:localhost:15672 user@server
    deploy:
      resources:
        limits:
          memory: 512m

  backend:
    build:
      context: ..
      dockerfile: deploy/Dockerfile.backend
    container_name: routebook-backend
    restart: unless-stopped
    env_file:
      - ../.env
    environment:
      DATABASE_URL: postgresql+asyncpg://${POSTGRES_USER}:${POSTGRES_PASSWORD}@db:5432/${POSTGRES_DB}
      DATABASE_URL_SYNC: postgresql+psycopg://${POSTGRES_USER}:${POSTGRES_PASSWORD}@db:5432/${POSTGRES_DB}
      REDIS_URL: redis://redis:6379/0
      CELERY_RESULT_BACKEND: redis://redis:6379/1
      CELERY_BROKER_URL: amqp://${RABBITMQ_USER}:${RABBITMQ_PASSWORD}@rabbitmq:5672//
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_healthy
      rabbitmq:
        condition: service_healthy
    command: >
      sh -c "alembic upgrade head &&
             uvicorn routebook.main:app --host 0.0.0.0 --port 8000 --workers 2"
    expose:
      - "8000"
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://localhost:8000/health')"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 60s

  worker:
    build:
      context: ..
      dockerfile: deploy/Dockerfile.backend
    container_name: routebook-worker
    restart: unless-stopped
    env_file:
      - ../.env
    environment:
      DATABASE_URL_SYNC: postgresql+psycopg://${POSTGRES_USER}:${POSTGRES_PASSWORD}@db:5432/${POSTGRES_DB}
      CELERY_RESULT_BACKEND: redis://redis:6379/1
      CELERY_BROKER_URL: amqp://${RABBITMQ_USER}:${RABBITMQ_PASSWORD}@rabbitmq:5672//
    depends_on:
      backend:
        condition: service_started
    command: >
      celery -A routebook.tasks.celery_app worker
      --loglevel=info
      --queues=default,ai_heavy,maintenance
      --concurrency=2
      --max-tasks-per-child=50
    deploy:
      resources:
        limits:
          memory: 1g

  beat:
    build:
      context: ..
      dockerfile: deploy/Dockerfile.backend
    container_name: routebook-beat
    restart: unless-stopped
    env_file:
      - ../.env
    environment:
      CELERY_BROKER_URL: amqp://${RABBITMQ_USER}:${RABBITMQ_PASSWORD}@rabbitmq:5672//
      CELERY_RESULT_BACKEND: redis://redis:6379/1
    depends_on:
      rabbitmq:
        condition: service_healthy
    command: celery -A routebook.tasks.celery_app beat --loglevel=info

  frontend:
    build:
      context: ..
      dockerfile: deploy/Dockerfile.frontend
    container_name: routebook-frontend
    restart: unless-stopped
    # 前端构建产物只是一个静态目录，用轻量镜像托管
    expose:
      - "80"

  caddy:
    image: caddy:2-alpine
    container_name: routebook-caddy
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    environment:
      DOMAIN: ${DOMAIN}
      EMAIL: ${ACME_EMAIL}
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
      - frontend_dist:/srv/frontend:ro
    depends_on:
      - backend
      - frontend

volumes:
  db_data:
  redis_data:
  rabbitmq_data:
  caddy_data:
  caddy_config:
  frontend_dist:
```

**几个关键决定的解释**

| 配置 | 为什么 |
|---|---|
| `pgvector/pgvector:pg16` 而不是官方 `postgres:16` | 官方镜像不含 pgvector 扩展，装了也用不了 |
| 数据库不暴露端口 | 减少攻击面。需要连的时候用 `docker compose exec db psql` |
| `--maxmemory-policy allkeys-lru` | Redis 存的是缓存和限流计数，内存满了淘汰旧数据是正确行为 |
| `--max-tasks-per-child=50` | Celery worker 处理 50 个任务后重启子进程，防止内存泄漏累积（AI 客户端库容易泄漏） |
| `--concurrency=2` | AI 任务都是 IO 等待，2 个够用；设太高会同时占满数据库连接池 |
| `deploy.resources.limits` | 防止某个容器吃光内存导致 OOM Killer 杀掉别的容器 |
| `frontend_dist` 共享 volume | 前端容器只负责构建，产物给 Caddy 托管 |

> **注意 `deploy.resources.limits` 在非 Swarm 模式下的可用性。** Docker Compose v2 支持它，但如果你的 Docker 版本较老不支持，改用 `mem_limit: 1g`（Compose v1 语法）。

开发时基础设施全在 Docker 里，前后端在宿主机跑。这样：

- 改代码立即热重载，不用重建镜像
- 可以用 IDE 的调试器断点
- 依赖关系（`localhost:5432` 等）与生产环境一致

## 4. Dockerfile

### 4.1 后端

**`deploy/Dockerfile.backend`**

```dockerfile
# ---- 构建阶段 ----
FROM python:3.12-slim AS builder

# uv 官方镜像里的二进制
COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/

WORKDIR /app

# 先只拷贝依赖描述文件 —— 利用 Docker 层缓存
# 只要 pyproject.toml / uv.lock 没变，这一层就不会重新执行
COPY backend/pyproject.toml backend/uv.lock ./

# 装到项目内的 .venv，不依赖系统 Python 环境
ENV UV_COMPILE_BYTECODE=1 \
    UV_LINK_MODE=copy
RUN --mount=type=cache,target=/root/.cache/uv \
    uv sync --frozen --no-dev --no-install-project

# 再拷贝源码
COPY backend/src ./src
COPY backend/alembic.ini ./
COPY backend/alembic ./alembic
RUN --mount=type=cache,target=/root/.cache/uv \
    uv sync --frozen --no-dev

# ---- 运行阶段 ----
FROM python:3.12-slim

# 非 root 用户运行
RUN groupadd --gid 1000 app && \
    useradd --uid 1000 --gid app --create-home app

WORKDIR /app

# 从构建阶段拷贝虚拟环境和代码
COPY --from=builder --chown=app:app /app /app

ENV PATH="/app/.venv/bin:$PATH" \
    PYTHONUNBUFFERED=1 \
    PYTHONDONTWRITEBYTECODE=1

USER app

EXPOSE 8000

CMD ["uvicorn", "routebook.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**三个关键点**

1. **先拷贝 `pyproject.toml` + `uv.lock`，再拷贝源码**。这样改业务代码不会导致重新装依赖，构建时间从 3 分钟降到 10 秒。
2. **`--mount=type=cache`** 缓存 uv 的下载缓存，加速重复构建。
3. **非 root 用户运行**。容器逃逸时能被限制在普通用户权限内。

### 4.2 前端

**`deploy/Dockerfile.frontend`**

```dockerfile
# ---- 构建阶段 ----
FROM node:22-alpine AS builder

RUN corepack enable && corepack prepare pnpm@latest --activate

WORKDIR /app

COPY frontend/package.json frontend/pnpm-lock.yaml ./
RUN --mount=type=cache,target=/root/.local/share/pnpm/store \
    pnpm install --frozen-lockfile

COPY frontend/ ./
RUN pnpm build

# ---- 运行阶段：极简 nginx ----
FROM nginx:alpine

COPY --from=builder /app/dist /usr/share/nginx/html
COPY deploy/nginx-frontend.conf /etc/nginx/conf.d/default.conf

EXPOSE 80
```

**`deploy/nginx-frontend.conf`**

```nginx
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    # SPA 路由 fallback：任何未匹配的路径都返回 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 带 hash 的静态资源可以长期缓存
    location ~* \.(js|css|woff2?|png|jpg|jpeg|svg|ico)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        access_log off;
    }

    # index.html 不缓存，保证发版后立即生效
    location = /index.html {
        add_header Cache-Control "no-cache, must-revalidate";
    }

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1024;
}
```

## 5. Caddy 配置

**`deploy/Caddyfile`**

```
{
    email {$EMAIL}
    # 生产建议开启，避免证书申请被限流
    acme_ca https://acme-v02.api.letsencrypt.org/directory
}

{$DOMAIN} {
    encode gzip zstd

    # ---- API ----
    handle /api/* {
        reverse_proxy backend:8000 {
            # SSE 必须关闭缓冲，否则流式输出会等全部生成完才推送
            flush_interval -1
            transport http {
                read_timeout 300s
                write_timeout 300s
            }
        }
    }

    handle /health {
        reverse_proxy backend:8000
    }

    # ---- 前端静态资源 ----
    handle {
        reverse_proxy frontend:80
    }

    # ---- 安全响应头 ----
    header {
        X-Content-Type-Options "nosniff"
        X-Frame-Options "DENY"
        Referrer-Policy "strict-origin-when-cross-origin"
        -Server
    }

    log {
        output file /data/access.log {
            roll_size 10mb
            roll_keep 5
        }
        format json
    }
}
```

> **`flush_interval -1` 是 SSE 的生命线。** 不设置它，Caddy 会缓冲响应体，用户看不到逐字输出。

**如果只想内部使用、不申请证书**，把域名换成 `:80` 或用 `tls internal`（自签证书）。

## 6. 环境变量

**`deploy/.env.production.example`** —— 复制为 `.env` 并填值

```bash
# ==================== 必填 ====================

# 域名（Caddy 用它申请 HTTPS 证书）
DOMAIN=routebook.example.com
ACME_EMAIL=you@example.com

# 数据库
POSTGRES_USER=routebook
POSTGRES_PASSWORD=<生成一个强密码>
POSTGRES_DB=routebook

# RabbitMQ
RABBITMQ_USER=routebook
RABBITMQ_PASSWORD=<生成一个强密码>

# ==================== 应用 ====================

ENV=production
DEBUG=false
SECRET_KEY=<openssl rand -hex 32 的输出>
LOG_LEVEL=INFO

# ==================== LLM ====================

LLM_PROVIDER=deepseek
LLM_API_KEY=sk-xxxxxxxx
LLM_MODEL=deepseek-chat
LLM_TEMPERATURE=0.3
AI_NEXT_STEP_ENABLED=true

EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_DIM=1536

# ==================== 限流 ====================

RATE_LIMIT_ENABLED=true
```

**生成强密码**：

```bash
openssl rand -base64 32
```

**安全要求**

| 项 | 要求 |
|---|---|
| `.env` 权限 | `chmod 600 .env` |
| `.env` 进 Git | **绝对禁止**。`.gitignore` 里必须有 `.env` |
| `DEBUG` | 生产必须是 `false`（否则会暴露 `/api/docs`） |
| `SECRET_KEY` | 必须随机生成，不能是默认值 |

## 7. 首次部署

### 7.1 服务器准备

```bash
# 1. 安装 Docker
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
newgrp docker

# 2. 验证
docker --version
docker compose version

# 3. 拉代码
git clone <your-repo> /opt/routebook
cd /opt/routebook

# 4. 配置环境变量
cp deploy/.env.production.example deploy/.env
vim deploy/.env          # 填入所有值
chmod 600 deploy/.env
```

### 7.2 域名解析

在 DNS 服务商处添加 A 记录：

```
routebook.example.com  →  你的服务器 IP
```

**等 DNS 生效后再启动 Caddy**，否则证书申请会失败（Let's Encrypt 需要能解析到你的服务器）。

验证：

```bash
dig +short routebook.example.com
# 应该返回你的服务器 IP
```

### 7.3 启动

```bash
cd /opt/routebook/deploy

# 构建镜像（第一次会慢，5-10 分钟）
docker compose build

# 启动
docker compose up -d

# 查看状态（所有服务应该是 Up 或 Up (healthy)）
docker compose ps

# 看日志
docker compose logs -f backend

# 健康检查
curl https://routebook.example.com/health
```

**预期输出**：

```json
{
  "status": "ok",
  "checks": { "api": "ok", "database": "ok", "redis": "ok" },
  "version": "1.0.0"
}
```

### 7.4 首次初始化

数据库迁移和种子数据由 `backend` 容器的启动命令自动执行（`alembic upgrade head`）。但**种子数据（默认用户 + 模板路线）需要手动执行一次**：

```bash
docker compose exec backend uv run python -m routebook.db.seed
```

### 7.5 启动检查清单

| # | 检查项 | 命令 / 方法 | 期望结果 |
|---|---|---|---|
| 1 | 所有容器运行 | `docker compose ps` | 全部 Up |
| 2 | 后端健康 | `curl .../health` | `status: ok` |
| 3 | 数据库连通 | 看 `/health` 的 `checks.database` | `ok` |
| 4 | Redis 连通 | 看 `/health` 的 `checks.redis` | `ok` |
| 5 | HTTPS 生效 | 浏览器访问域名 | 锁图标，无警告 |
| 6 | 前端可访问 | 浏览器打开首页 | 页面正常渲染 |
| 7 | API 可达 | 浏览器控制台无 404 | |
| 8 | Celery 有 worker | `docker compose logs worker \| grep ready` | 有 `celery@... ready` |
| 9 | RabbitMQ 队列建立 | 访问 `http://localhost:15672`（SSH 隧道） | 看到 3 个队列 |
| 10 | 节点数据已导入 | 前端能看到 26 个知识点 | |

**SSH 隧道访问 RabbitMQ 管理界面**：

```bash
ssh -L 15672:localhost:15672 user@server
# 然后本地浏览器打开 http://localhost:15672
```

但生产 compose 里 RabbitMQ 没有映射 15672 端口。需要临时加：

```bash
docker compose exec rabbitmq rabbitmqctl list_queues name messages
```

## 8. 日常运维

### 8.1 常用命令

```bash
cd /opt/routebook/deploy

# 查看状态
docker compose ps

# 查看日志（最近 100 行，跟随）
docker compose logs -f --tail=100 backend
docker compose logs -f worker

# 重启单个服务
docker compose restart backend

# 更新代码后重新部署
git pull
docker compose build backend frontend
docker compose up -d backend frontend caddy

# 进入容器
docker compose exec backend bash
docker compose exec db psql -U routebook -d routebook

# 查看资源占用
docker stats
```

### 8.2 日志查看

```bash
# 后端错误日志（JSON 格式，用 jq 过滤）
docker compose logs backend --since 1h | jq -r 'select(.level=="error") | .event'

# Celery 任务失败
docker compose logs worker --since 1h | grep -i "task failed"

# 慢请求
docker compose logs backend --since 1h | jq -r 'select(.duration_ms > 1000) | "\(.path) \(.duration_ms)ms"'
```

### 8.3 数据库备份

**`scripts/backup.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

BACKUP_DIR=/opt/routebook/backups
RETENTION_DAYS=7
TIMESTAMP=$(date +%Y%m%d_%H%M%S)

mkdir -p "$BACKUP_DIR"

# 全量备份
docker compose -f /opt/routebook/deploy/docker-compose.yml \
    exec -T db pg_dump -U routebook -Fc routebook \
    > "$BACKUP_DIR/routebook_$TIMESTAMP.dump"

# 校验备份非空
if [ ! -s "$BACKUP_DIR/routebook_$TIMESTAMP.dump" ]; then
    echo "ERROR: 备份文件为空！" >&2
    exit 1
fi

echo "备份完成: routebook_$TIMESTAMP.dump ($(du -h "$BACKUP_DIR/routebook_$TIMESTAMP.dump" | cut -f1))"

# 清理旧备份
find "$BACKUP_DIR" -name "routebook_*.dump" -mtime +$RETENTION_DAYS -delete

echo "已清理 $RETENTION_DAYS 天前的备份"
```

**加入 crontab**：

```bash
sudo crontab -e

# 每天凌晨 2 点备份
0 2 * * * /opt/routebook/scripts/backup.sh >> /var/log/routebook-backup.log 2>&1

# 每周日凌晨 3 点复制一份到异地（可选，但强烈建议）
0 3 * * 0 rsync -az /opt/routebook/backups/ user@backup-host:/backups/routebook/
```

**异地备份的意义**：服务器磁盘坏了，本地备份一起没。至少复制到另一个地方。

### 8.4 恢复

```bash
# 1. 停掉后端（避免写入冲突）
docker compose stop backend worker beat

# 2. 恢复
docker compose exec -T db pg_restore \
    -U routebook -d routebook --clean --if-exists \
    < /opt/routebook/backups/routebook_20261012_020000.dump

# 3. 重启
docker compose start backend worker beat

# 4. 验证
curl https://routebook.example.com/health
```

**恢复演练**：**每季度做一次**。没演练过的备份等于没有备份 —— 你可能在真正需要的时候才发现备份是坏的。

演练方法：在本地起一个 compose 环境，把生产备份恢复进去，验证数据完整。

### 8.5 升级流程


## 9. 监控

### 9.1 最小可用的监控

**个人项目不需要 Prometheus + Grafana。** 用最简单的方案：

**`scripts/healthcheck.sh`** —— 每 5 分钟跑一次，异常时发邮件

```bash
#!/usr/bin/env bash
set -uo pipefail

URL="https://routebook.example.com/health"
LOG=/var/log/routebook-health.log

response=$(curl -s -m 10 -w "\n%{http_code}" "$URL" || echo -e "\n000")
body=$(echo "$response" | head -n -1)
code=$(echo "$response" | tail -n 1)

if [ "$code" != "200" ]; then
    echo "$(date -Iseconds) FAIL http_code=$code" >> "$LOG"
    # 发邮件告警（需要配置 msmtp 或类似工具）
    echo "Routebook 健康检查失败：HTTP $code" | mail -s "[Routebook] 服务异常" you@example.com
    exit 1
fi

if ! echo "$body" | grep -q '"status":"ok"'; then
    echo "$(date -Iseconds) DEGRADED body=$body" >> "$LOG"
    exit 1
fi

echo "$(date -Iseconds) OK" >> "$LOG"
```

### 9.2 需要关注的指标

| 指标 | 怎么查 | 告警阈值 |
|---|---|---|
| 服务可用性 | `healthcheck.sh` | 连续 2 次失败 |
| 磁盘使用 | `df -h /` | > 85% |
| 内存使用 | `free -h` | 可用 < 500MB |
| AI 降级频率 | 日志中 `ai.degraded` 的条数 | 每天 > 20 次 |
| AI 成本 | `/api/v1/stats/overview` 的 `ai_usage` | 超过预算 |
| Celery 队列积压 | Flower 或 `rabbitmqctl list_queues` | 任一队列 > 100 |
| 数据库连接数 | `SELECT count(*) FROM pg_stat_activity` | > 80 |

**磁盘告警特别重要**：Docker 的日志和 volume 会悄悄涨。定期清理：

```bash
# 清理未使用的镜像和构建缓存
docker system prune -a --volumes

# ⚠️ 注意 --volumes 会删除未使用的 volume，执行前确认没有重要数据在未挂载的 volume 里
```

**更安全的清理**：

```bash
docker image prune -a       # 只清理镜像
docker builder prune        # 只清理构建缓存
```

## 10. 故障排查

### 10.1 常见问题速查

| 症状 | 可能原因 | 排查 |
|---|---|---|
| 502 Bad Gateway | backend 挂了 | `docker compose logs backend` |
| 前端白屏 | 构建产物有问题 / API 不通 | 浏览器控制台看报错 |
| SSE 不流式输出 | Caddy 缓冲 | 检查 `flush_interval -1` |
| 页面能开但数据空 | 前端 API 地址错 | 检查 `VITE_API_BASE_URL` |
| AI 一直降级 | LLM Key 无效 / 超时 | 看日志 `ai.degraded` 的 reason |
| 队列任务不执行 | worker 没起来 | `docker compose logs worker` |
| 任务卡在 running | worker 崩溃 | 等 cleanup 任务清理，或手动改状态 |
| 证书申请失败 | DNS 没生效 / 80 端口不通 | `dig` 验证；检查防火墙 |
| 数据库连接耗尽 | 事务中做 IO | 检查是否有长事务 |

### 10.2 具体排查步骤

#### 后端无法启动

```bash
# 1. 看日志
docker compose logs --tail=100 backend

# 2. 常见错误
# "could not connect to server"  → 数据库没起来，检查 depends_on 和 db 健康状态
# "relation does not exist"      → 迁移没跑，手动执行 alembic upgrade head
# "ModuleNotFoundError"          → 依赖没装全，重新 build
# "permission denied"            → volume 权限问题
```

#### Celery worker 不消费任务

```bash
# 1. 确认 worker 起来了
docker compose logs worker | grep "ready"

# 2. 确认队列存在且绑定正确
docker compose exec rabbitmq rabbitmqctl list_queues name messages consumers

# 期望：每个队列都有 1 个 consumer

# 3. 确认 worker 监听对了队列
docker compose logs worker | grep "queues"

# 4. 手动投递一个测试任务
docker compose exec backend uv run python -c "
from routebook.tasks.celery_app import celery_app
r = celery_app.send_task('routebook.tasks.maintenance.cleanup_stale_jobs')
print('task id:', r.id)
"
```

#### AI 调用失败

```bash
# 1. 直连测试 LLM
docker compose exec backend uv run python -c "
import asyncio
from routebook.core.config import settings
from routebook.ai.provider import create_llm_provider

async def main():
    p = create_llm_provider(settings)
    print('provider:', p.model_name)
    r = await p.complete([{'role': 'user', 'content': 'ping'}])
    print('response:', r[:100])

asyncio.run(main())
"

# 2. 检查 key 是否有效（常见错误）
#    - key 前后有空格
#    - key 已过期
#    - base_url 配错
#    - 账户余额不足
```

#### 数据库连接耗尽

```bash
docker compose exec db psql -U routebook -d routebook -c "
SELECT pid, state, wait_event_type, now() - query_start AS duration,
       left(query, 80) AS query
FROM pg_stat_activity
WHERE datname = 'routebook' AND state != 'idle'
ORDER BY duration DESC;
"
```

**如果看到 `duration` 超过 30 秒的查询**，八成是有人忘了在事务里做外部 IO（见 `04` §4.2）。

### 10.3 紧急回滚

```bash
cd /opt/routebook

# 1. 回滚代码
git log --oneline -5
git checkout <上一个好的 commit>

# 2. 重新构建启动
cd deploy && docker compose build && docker compose up -d

# 3. 如果涉及数据库迁移，回滚迁移
docker compose exec backend alembic downgrade -1
```

## 11. 安全加固清单

上线前逐项确认：

| # | 项 | 检查方式 |
|---|---|---|
| 1 | `.env` 不在 Git 里 | `git log --all --full-history -- '*.env'` 应无输出 |
| 2 | `.env` 权限 600 | `ls -l deploy/.env` |
| 3 | `DEBUG=false` | 访问 `/api/docs` 应返回 404 |
| 4 | `SECRET_KEY` 已随机生成 | 不是默认值 |
| 5 | 数据库端口未暴露 | `docker compose ps` 中 db 没有 `0.0.0.0:5432` |
| 6 | RabbitMQ 管理端口未暴露 | 同上 |
| 7 | SSH 禁用密码登录 | `grep PasswordAuthentication /etc/ssh/sshd_config` 应为 no |
| 8 | 防火墙只开 22/80/443 | `sudo ufw status` |
| 9 | HTTPS 正常 | 浏览器无警告 |
| 10 | 安全响应头已设置 | `curl -I https://域名` 检查 |
| 11 | 自动备份已配置 | `crontab -l` |
| 12 | **备份恢复演练过** | 能从备份恢复出可用环境 |
| 13 | 限流生效 | 快速连点 AI 按钮，应被限流 |
| 14 | 日志中无 API Key | `docker compose logs backend \| grep -i "sk-"` 应无输出 |

**第 12 项是最容易被跳过、也最要命的。** 没有演练过的备份不叫备份。

## 12. 资源清理

### 12.1 数据库定期维护

```sql
-- 查看表大小
SELECT relname AS table,
       pg_size_pretty(pg_total_relation_size(relid)) AS total_size
FROM pg_catalog.pg_statio_user_tables
ORDER BY pg_total_relation_size(relid) DESC;

-- 清理已取消/很久以前完成的任务
DELETE FROM study_tasks
WHERE status IN ('done', 'cancelled') AND updated_at < now() - interval '90 days';

-- 清理旧的复习日志（保留 1 年）
DELETE FROM review_logs WHERE reviewed_at < now() - interval '1 year';

-- 清理旧的 AI 作业记录（保留 30 天）
DELETE FROM ai_jobs WHERE created_at < now() - interval '30 days' AND status IN ('succeeded', 'failed');
```

建议把这些做成一个每月执行的 Celery 任务，而不是手工跑。

### 12.2 Docker 磁盘

```bash
# 查看占用
docker system df

# 安全清理（不删 volume）
docker system prune -f

# 查看各 volume 大小
du -sh /var/lib/docker/volumes/*
```

**注意**：不要随便执行 `docker system prune --volumes`。`db_data` 和 `rabbitmq_data` 都是 volume，删了数据就没了（虽然在用中的 volume 不会被删，但风险不值得冒）。
