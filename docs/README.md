# Routebook 文档集 · 使用指南

> Routebook（路书）是一个**自我驱动的学习助手**：它记录你在哪、判断你去哪、推着你往前走。

---

## 这套文档是什么

这是 Routebook 的**全部设计依据**。目标是：任何人（或任何 AI 助手）只拿着这套文档，就能从零把这个项目做出来，**不需要再问任何人任何问题**。

因此这套文档遵循三条硬约定：

1. **自包含**：不引用任何外部对话、聊天记录或口头约定。所有决策、参数、字段、命令都写在文档里。
2. **可执行**：每个技术决策都写清了"选什么、为什么、替代方案是什么"；每个接口都有完整的请求/响应示例；每张表都有完整 DDL。
3. **可验收**：每个开发里程碑都有明确的、可判定的完成标准，不写"基本完成"这种模糊描述。

---

## 怎么用这套文档

### 如果你是人（开发者）

1. 先读 `01-产品设计.md`，建立对"这个产品到底是什么"的完整认知。**不要跳过这一步**——后面所有技术决策都是从产品定义推导出来的。
2. 读 `03-技术架构.md`，理解整体分层和技术选型理由。
3. 打开 `08-开发计划.md`，从 M0 里程碑开始，一个里程碑一个里程碑地做。
4. 做到哪一步，需要细节时，再翻对应的详细文档（`02` `04` `05` `06` `07`）。

### 如果你在用一个 AI 助手辅助开发

把 `08-开发计划.md` 里当前里程碑的任务描述**整段复制**给 AI，并让它先读对应章节的文档。文档里的接口契约和数据模型是唯一的真相来源（single source of truth），AI 的输出如果和文档冲突，**以文档为准**。

一个有效的提示词模板：

```
你正在协助开发 Routebook 项目。
请先阅读以下文档，理解背景和约束：
- docs/01-产品设计.md
- docs/02-领域模型与数据库设计.md
- docs/04-后端设计.md

本次任务：实现 M2 里程碑中的「节点进度更新接口」
要求：
1. 严格遵守文档中定义的数据模型和 API 契约，字段名不得改动
2. 完成后对照该里程碑的验收标准逐条自检
3. 如果文档中有任何不明确的地方，先指出并询问，不要自行假设
```

## 技术栈速览

| 层 | 技术 | 说明 |
|---|---|---|
| 后端语言 | Python 3.12 | |
| 包管理 | **uv** | 极快的依赖解析与虚拟环境管理 |
| Web 框架 | **FastAPI** | 原生 async，自动生成 OpenAPI 文档 |
| ORM | SQLAlchemy 2.0 (async) + Alembic | 迁移用 Alembic |
| 数据校验 | Pydantic v2 | FastAPI 原生集成 |
| 主数据库 | **PostgreSQL 16** | 关系数据 + JSONB |
| 向量检索 | **pgvector** 扩展 | 不引入独立向量库，降低运维成本 |
| 缓存 | **Redis 7** | 缓存、限流、分布式锁、Celery 结果后端 |
| 消息队列 | **RabbitMQ 3.13** | 异步任务的消息代理 |
| 任务队列 | **Celery 5.x** | broker 用 RabbitMQ，backend 用 Redis |
| 前端框架 | **Vue 3.5** + **TypeScript 5** | |
| 构建工具 | Vite 6 | |
| 状态管理 | Pinia | |
| UI 组件 | Naive UI | 对 TypeScript 友好 |
| 反向代理 | Caddy 2 | 自动申请和续签 HTTPS 证书 |
| 容器化 | Docker + Docker Compose | |

> **关于消息队列的选型**：本项目选用 RabbitMQ 而不是 Kafka。理由是 Kafka 面向高吞吐日志流场景，对个人项目属于严重过度设计；RabbitMQ 提供标准的 AMQP 语义（交换机、路由键、死信队列、延迟队列），运维成本低，学习价值高。如果后期希望进一步简化，可以用 `Taskiq`（async 原生）替换 Celery，broker 仍然可以复用 RabbitMQ——替换方式见 `04-后端设计.md`。

## 一句话架构

```
浏览器 (Vue3 + TS)
      │  HTTP / SSE
      ▼
反向代理 (Caddy)
      │
      ▼
API 服务 (FastAPI)  ──── Redis (缓存/限流)
      │      │
      │      └──────────► RabbitMQ ──► Celery Worker ──► LLM API
      │                                        │
      └──────────────► PostgreSQL (+pgvector) ◄┘
```

**同步请求走 FastAPI 直连数据库；耗时任务（AI 生成、向量化、统计聚合）丢给 RabbitMQ 交给 Celery Worker 异步处理；AI 对话用 SSE 流式直返，不进队列。**

详细展开见 `03-技术架构.md`。
