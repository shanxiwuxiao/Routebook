## 二、A 类：必须修（会直接拦住你）

### A1 · 后端在 `backend/` 目录下根本起不来 🔴 最高优先级

**复现**（在 `backend/` 下）：

```
$ uv run python -c "from routebook.core.config import settings"
pydantic_core._pydantic_core.ValidationError: 5 validation errors for Settings
DATABASE_URL / DATABASE_URL_SYNC / REDIS_URL / CELERY_RESULT_BACKEND / CELERY_BROKER_URL
  Field required [type=missing]
```

**原因**：`core/config.py` 里 `env_file=".env"` 是相对 **当前工作目录** 解析的。`.env` 在仓库根，而你按 `03-技术架构.md` §8.2 的写法是 `cd backend` 之后启动 → `backend/.env` 不存在 → 所有必填字段全丢。

**注意一个隐藏事实**：我实测你 8000 端口上**已经有服务在跑**（PID 3408），说明你一直是从**仓库根目录**启动的。也就是说，你的启动方式和文档写的方式不是同一种——今天能用，是因为你记得怎么启动；换台机器、或者几个月后你自己照文档敲一遍，就是必崩。

**这是文档本身的 bug**：`04-后端设计.md` §8.2 给的 `env_file=".env"` 与 `03-技术架构.md` §8.2 的 `cd backend && uv run uvicorn ...` 互相矛盾。建议**改代码而不是改文档**（根目录放 `.env` 更符合 M10 部署时的约定）。

**修复方案**（`backend/src/routebook/core/config.py`）：

```python
from pathlib import Path
from pydantic_settings import BaseSettings, SettingsConfigDict

# backend/src/routebook/core/config.py → 仓库根（已实测 parents[4] 正确）
REPO_ROOT = Path(__file__).resolve().parents[4]

class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=REPO_ROOT / ".env",
        env_file_encoding="utf-8",
        extra="ignore",
    )
```

我已实测：改成绝对路径后，在 `backend/` 目录下能正确读到根 `.env`。

> 更健壮的写法（不依赖层级硬编码）：从 `Path(__file__).resolve().parents` 逐层向上找第一个含 `.env` 的目录。好处是你以后挪动文件位置不会炸。

**验收**：`cd backend && uv run uvicorn routebook.main:app --port 8000` 能正常起来。

### A4 · `ruff` 和 `mypy` 两条验收没过 🔴

**ruff（3 个错误，全部可自动修）**：

```
src/routebook/core/config.py:1:1  I001  Import block is un-sorted
src/routebook/core/logging.py:1:1 I001  Import block is un-sorted
src/routebook/main.py:1:1         I001  Import block is un-sorted
```

根因不是代码问题，是 **`backend/pyproject.toml` 里没有 `[tool.ruff]` 配置**，所以 ruff 用的是默认规则集。

**mypy（5 个错误）**：

```
src/routebook/core/config.py:41: error: Missing named argument "DATABASE_URL" for "Settings"
（DATABASE_URL_SYNC / REDIS_URL / CELERY_RESULT_BACKEND / CELERY_BROKER_URL 同样）
```

这是 pydantic-settings + mypy 的经典问题：mypy 不认识"字段从环境变量注入"，把没默认值的字段当成了必填构造参数。

**修复**：`docs/09-开发规范.md` §2.1 **已经把这两个工具的完整配置写好了**，直接照抄进 `backend/pyproject.toml`。

我已实测：
- 加上 `[tool.mypy] plugins = ["pydantic.mypy"]` → mypy 从 5 错变 **0 错**
- 照抄 §2.1 的 `strict = true` 之后，会**新暴露 2 个真实问题**（见 A5）
- ruff 的 3 个 I001 用 `uv run ruff check . --fix` 一次修完

> 抄的时候注意 §2.1 里 `[[tool.mypy.overrides]]` 引用了 `celery.*`、`alembic.*`，这两个包还没装——mypy 不会因为 overrides 里写了未安装的模块而报错，可以现在一起放进去，M1/M8 直接用。

### A5 · `core/logging.py` 是死代码，从未被调用 🟠

```
$ grep -rn "configure_logging" backend/src
backend/src/routebook/core/logging.py:9: def configure_logging() -> None:   ← 只有定义，没有调用
```

`main.py` 里既没 import `routebook.core.logging`，也没调 `configure_logging()`。所以你现在看到的日志是 **structlog 的默认配置**输出的，不是你自己写的那套 JSON 格式化。

**修复**（两处，几分钟）：

1. `main.py` 顶部调用 `configure_logging()`——**必须在创建 app 之前**调用，否则最早的日志会漏掉
2. 加上类型标注。照抄 §2.1 的 strict 配置后，`main.py` 会新报 2 个错：

```
main.py:8  error: Function is missing a type annotation      [no-untyped-def]
main.py:18 error: Function is missing a return type annotation [no-untyped-def]
```

我已实测以下写法可以通过 strict mypy：

```python
from collections.abc import AsyncIterator

@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    yield

async def health_check() -> dict[str, str]:
    return {"status": "ok", ...}
```

**另外提醒一个坑（先别急着深挖）**：`logging.py` 里 `ProcessorFormatter` 和 `structlog.configure()` **共用同一个 `processors` 列表**，而这个列表末尾带着 renderer。标准写法要求把它们拆开：

```
shared_processors = [...共用的前处理...]
structlog.configure(processors=shared_processors + [ProcessorFormatter.wrap_for_formatter])
ProcessorFormatter(foreign_pre_chain=shared_processors, processors=[remove_processors_meta, renderer])
```

不拆的后果是**日志可能出现双重渲染/JSON 被转义**。**今天的动作**：先把它调用起来、看实际输出长什么样；如果输出正常就先放着（M1 会大量看日志，那时候再修收益更大）。

## 三、B 类：与文档/验收标准不一致（建议今天一起补）

### B1 · Swagger 和 OpenAPI 的路径不对

**实测**：

```
GET /api/docs          -> 404     ← 验收标准要求 200
GET /docs              -> 200
GET /openapi.json      -> 200
GET /api/openapi.json  -> 404     ← 05 §3.1 生成前端类型时要访问的地址
GET /api/v1/health     -> 404
```

**修复**：`FastAPI(lifespan=lifespan, docs_url="/api/docs", openapi_url="/api/openapi.json")`，顺便补上 `title="Routebook API"` 和 `version`。

**为什么值得现在改**：M2 要跑 `openapi-typescript http://localhost:8000/api/openapi.json`。现在定好路径，M2 一行不用改。

### B2 · `/health` 的 `env` 字段是硬编码的

现在返回 `"env": "development"` 是一个**字符串字面量**，不读 `settings.ENV`。你哪天在 `.env` 里把 `ENV` 改成 `production`，这个接口还会告诉你 `development`——**接口在撒谎，而这类 bug 永远不会报错**。

**修复**：`"env": settings.ENV`；`version` 建议改成 `importlib.metadata.version("routebook")`（`pyproject.toml` 里已经是 0.1.0）。

### B3 · CORS 中间件没启用

**实测**：`OPTIONS /health`（带 Origin 头）→ **405，没有任何 CORS 响应头**。

现在页面能用，是因为你走的是 Vite 代理（同源），绕过了浏览器跨域检查。但 `config.py` 里的 `cors_origins_list()` 目前是**死代码**，而 `08-开发计划.md` M0 常见坑表里明确写了"CORS 没配 → 前端请求全部被浏览器拦截"。

**修复**：`app.add_middleware(CORSMiddleware, allow_origins=settings.cors_origins_list(), ...)`。这是我刚写的方法，你在 `config.py` 里已经实现了，直接用。

### B4 · `apiClient` 的前缀和 proxy rewrite 会打架（**路径约定必须现在定**）

- proxy 规则：`rewrite: (path) => path.replace(/^\/api/, '')` —— **删掉 `/api` 前缀**
- `probeClient`（baseURL `/api`）→ 请求 `/api/health` → 后端 `/health` ✅ **对的**
- `apiClient`（baseURL `/api/v1`）→ 请求 `/api/v1/xxx` → 后端 `/v1/xxx` ❌ **后端没有这个前缀**

现在没暴露，是因为 `apiClient` 还没有任何调用方。**M2 写的第一个接口（`GET /routes`）就会撞上**。

**现在拍板**，二选一：

| 方案 | proxy 怎么写 | 后端怎么挂 | 评价 |
|---|---|---|---|
| **方案 1（推荐）** | 只对 `/api/v1` 做 rewrite，删掉 `/api/v1` 前缀；`/api/health` 不 rewrite | 业务接口挂 `/v1`，探针挂 `/` | 前缀只在一处定义 |
| **方案 2** | 完全不 rewrite | 所有接口（含业务）都挂在 `/api/v1` 下 | 后端路径带 `/api` 有点冗余，但最简单 |

不管选哪个，都要**同步改 3 处**：`vite.config.ts` 的代理、`.env.development` 的 `VITE_API_BASE_URL`、以及后端路由的挂载前缀。

### B5 · `main.py` 里的 `uvicorn.run("main:app")` 是错的

```python
if __name__ == "__main__":
    uvicorn.run("main:app", host="0.0.0.0", port=8000)
```

- `"main:app"` 这个模块路径不存在，正确写法是 `"routebook.main:app"`。现在直接 `python main.py` 会 ImportError（不过你平时用 `uvicorn` 命令，所以没暴露）
- `host="0.0.0.0"` 在开发环境意味着**局域网里任何人都能访问你的开发机**。开发用 `127.0.0.1`，`0.0.0.0` 留给容器里跑的时候

### B6 · `core/` 目录缺 `__init__.py`

```
backend/src/routebook/          __init__.py ✅
backend/src/routebook/core/     ❌ 没有
```

现在能 import 靠的是 Python 3.3+ 的**命名空间包**，属于"能跑但不标准"。打包成 wheel、以及部分工具链（含 M1 的测试收集）会出现意外。

**修复**：`core/` 下补 `__init__.py`（空文件即可），并顺手建 `backend/tests/` 目录（M1 要用）。

### B7 · redis 没有 healthcheck

验收标准写的是"三个服务都是 healthy"，但实测 redis 只有 `Up`（没有健康的括号）。**要么**给 redis 加 healthcheck（5 行，`redis-cli ping`），**要么**把验收标准改成"db + rabbitmq healthy，redis Up"。

——顺手说一句：`flower` 容器现在是 `Up` 但**没有任何 worker**，M8 之前它就是个空壳。留着不占多少资源，也可以现在就注释掉。
